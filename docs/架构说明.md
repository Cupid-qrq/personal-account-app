# Ledger Atlas 3 · 架构与数据契约

## 运行结构

```text
浏览器 React / TypeScript / shadcn/ui / Recharts
  ├─ Vite 开发端口 5173 → /api 代理 → 8000
  └─ 生产：FastAPI 8000 同时提供 / 与 /assets
                       ↓
FastAPI 查询、导入、预算与月度手记接口
  ├─ analytics.py：从标准主表计算统计，前端不重复定义统计口径
  ├─ imports.py → ingest.py：预览校验、按 ID 合并、生成快照
  └─ preferences.py：共享月度预算、手记和月结状态
                       ↓
data/origin → processed_atlas CSV + SQLite + 清单 → archive_atlas 月度镜像
data/settings.json：budgets + reviews
```

生产前端必须 `npm run build`。`app.py` 导出 ASGI 应用，`server.py` 是本地启动入口。数据查询当前以标准 CSV 加载至 pandas 为主，SQLite 是可互操作的持久镜像，不声称所有查询都经过数据库。

## 前端分层

- `src/App.tsx`：布局、月份、路由、全局浮层。`lib/location.ts` 维护 URL 与后退历史。
- `pages/`：总览、分析、账单、数据管理；`React.lazy` 按需加载。
- `components/ui/`：shadcn CLI 生成的 Radix 组件，经本地样式与中文可访问名称调整。
- `components/charts.tsx`：Recharts 图表、工具提示、数据表；在实际容器测量后绘制，避免手机使用桌面预估尺寸。
- `components/dialogs.tsx`：预算、导入预览 / 提交、账单详情。令牌仅保存在当前浮层内存中。
- `components/month-review.tsx`：共享手记、月结状态、未保存草稿提示、触摸设备焦点策略；使用 shadcn Dialog / Textarea / Select。
- `components/motion.tsx`：系统与本地动效偏好、单一滚动监听、段落 IntersectionObserver / Web Animations。`chapter.tsx` 提供月份纸卡、手记入口和正文。
- `lib/api.ts` / `types.ts`：请求、错误、接口类型；TanStack Query 管理缓存、请求取消与变更后刷新。
- `index.css`：基础设计变量、页面布局、响应式、焦点与打印样式。`motion.css`：3.1 纸卡、动效、手记、差异预览和减少动态效果覆盖层。

## 数据契约和合并

必需来源列：`ID、时间、分类、类型、金额`。可选列包括 `账本、二级分类、币种、账户1、账户2、备注、已报销、手续费、优惠券、记账者、账单标记、标签、账单图片、关联账单`；派生 `日期、月份、年份`。

ID 按字符串读取，保留前导零。文件内同 ID 取最后一行；跨文件按来源顺序取最后一条，再按交易时间排序。手工来源按文件名顺序，界面确认上传的 `upload_` 文件优先，并按微秒时间戳排序。因此更正交易日期为更早时间也不会被旧记录覆盖。

预览只读取，不落盘；确认时重新校验。上传支持 CSV / XLSX / XLS，限制 10 MB。当前只接受人民币收入与支出；不将转账直接加入生活费统计。分类仍使用 `config.py` 中的固定映射，未知分类会标准化为「其它 / 未分类」，分类自定义属于下一阶段。

差异比较使用标准化后的原始字段，不比较派生年月日：时间统一到秒、金额统一两位小数、空值与文本统一后比较。`updated_rows` 是有字段变化的已有 ID 数，`unchanged_rows` 是内容相同的已有 ID 数；`changes` 最多返回 20 条带 `field / before / after` 的记录，`changes_truncated` 表示剩余变更未展开。缺省可选字段按导入规范清空，界面会显示这一差异；它不是局部字段 PATCH。总量不受明细截断影响。

## 查询接口

| 方法与路径 | 用途 |
| --- | --- |
| GET `/api/health` | 版本、记录数、写入是否需要管理令牌 |
| GET `/api/summary?month=YYYY-MM` | 汇总、趋势、分类、日度、近期记录、观察、预算、覆盖范围、review |
| GET `/api/patterns?month=YYYY-MM` | 二级分类和消费节律 |
| GET `/api/transactions?month=YYYY-MM` | 月份全量明细；前端筛选后按 15 条分页 |
| GET `/api/data-room` | 文件清单、哈希、字段与重复 ID |
| POST `/api/import/preview` | multipart 文件校验、新增 / 变更 / 相同数量、字段前后差异 |
| POST `/api/import` | 校验后保存来源、重建、刷新缓存 |
| PUT `/api/budgets/{month}` | JSON `amount`；正数为预算，null 为取消 |
| PUT `/api/reviews/{month}` | JSON `note`（最多 800 字符）、`status`（auto / in_progress / closed）；月份须已有账单 |

无效月份查询回落到数据中的最近月份，响应 `month` 表示实际选择。未设置管理令牌时允许本地写入；配置 `LEDGER_ADMIN_TOKEN` 后，所有上述写入与预览接口要求 `X-Admin-Token`。阅读认证应由部署入口提供。

## 统计定义

金额按来源收支类型统计，结余 = 收入 − 支出；不是银行卡实际余额。月结状态作用如下：

- `auto`：最新月份最后记账日早于月末时按部分月份统计，历史月份默认按整月；这只是推断，并不证明没有漏记。
- `in_progress`：包括历史月份在内，按月初至最后记账日计算日均，环比比较上月同日区间。
- `closed`：用户确认月结，日均按整月自然日计算，比较上月整月；可随时改回，不禁止后续更正。

缺少上月记录、上月支出为零、或上月明确仍在记录且覆盖不足时，不计算百分比。上月覆盖先根据整月记录确定，再切出可比区间，避免把区间末尾没有消费误认为覆盖不足。当前显式截止日尚未实现，仍以最后记账日作为未月结月份的覆盖终点。

每日缺少记录时图表补零，只表示该日没有支出记录。未月结月份的月历超过覆盖范围的格子不可点击，明确标记未收录。年度图表按当前选择年份过滤。所有分析只描述已经导入的数据。

## 持久化与并发边界

预算与手记通过同一设置锁读取并更新对应区段，先写临时文件再替换；修改手记保留其他月份及已有预算。`reviews[YYYY-MM]` 包含 `note / status / updated_at`（UTC ISO 时间）。动效偏好保存在各浏览器 `localStorage`，不改变共享设置；系统减少动态效果始终优先。

导入和读取通过同一进程锁协调；重建失败会移除本次新来源并尝试恢复旧快照。SQLite 连接明确关闭。该机制适用于单进程家庭应用；多文件快照尚未实现崩溃级原子事务，不配置多个 worker。生产备份应覆盖整个 `data/`，不能只复制 SQLite。

`data/origin` 是事实来源；直接手工放入文件后需要运行重建命令。旧月度归档属于派生镜像，主查询始终以主表为准。严格原子版本、批次撤销、整数分金额模型见总体规划。
