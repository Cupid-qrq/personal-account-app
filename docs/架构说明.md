# Ledger Atlas 2.0 架构说明

## 运行时分层

```text
data/origin/*.csv|*.xlsx|*.xls
            │
            ▼
backend/ingest.py  ── 统一字段、金额、类型、分类、时间、ID 去重
            │
            ├── data/processed_atlas/ledger_atlas.csv
            ├── data/processed_atlas/ledger_atlas.sqlite3
            ├── data/processed_atlas/dataset_manifest.json
            └── data/archive_atlas/YYYY-MM.csv
            │
            ▼
backend/analytics.py  ── 月度汇总、趋势、分类、节律、洞察
            │
            ▼
backend/api.py  ── FastAPI JSON API + 文件导入 + 静态资源服务
            │
            ▼
frontend/index.html + styles.css + app.js  ── 浏览器交互与 SVG/CSS 可视化
```

## 数据契约

源字段保留账单导出的 19 个字段，其中 `账本` 是 2026-10 Excel 新增字段；系统再生成 `日期`、`月份`、`年份` 三个派生字段。所有记录必须有非空 `ID` 和可解析 `时间`，金额统一为非负数，收入/支出由 `类型` 和分类别名共同判断。

每次全量重建都会扫描 `data/origin/` 下所有 CSV/XLSX/XLS 文件，按 `ID` 合并并以排序后的最后一条为准。清单记录源文件大小、SHA-256、行数、月份覆盖、类型分布和主表 SHA-256，便于复核数据是否发生了意外变化。

## API

| 路径 | 作用 |
| --- | --- |
| `GET /api/health` | 服务和数据行数检查 |
| `GET /api/summary?month=YYYY-MM` | 指标、趋势、分类、日度、最近记录与规则洞察 |
| `GET /api/patterns?month=YYYY-MM` | 分类动量、二级分类和星期画像 |
| `GET /api/transactions?month=YYYY-MM` | 当前月份全部明细 |
| `GET /api/data-room` | 数据清单、重复 ID、字段契约和空值概览 |
| `POST /api/import` | 导入 CSV/XLSX/XLS 后触发全量重建 |

当设置 `LEDGER_ADMIN_TOKEN` 时，导入接口要求 `X-Admin-Token`。未设置时适合本地家庭网络使用，但不适合直接暴露到公共网络。

## 部署边界

前端是无构建步骤的静态资源，可部署到 GitHub Pages / Cloudflare Pages。上传、SQLite 和全量重建必须留在 FastAPI 服务端，因此需要配置 API 地址或由 FastAPI 同源托管静态文件。当前版本选择同源托管作为默认路径，降低家庭用户的配置成本。
