# Ledger Atlas 3 · 开发总体规划

更新：2026-10-16。本文是独立重构后的唯一开发路线；旧 Streamlit 规划及上一版展示页规划不再适用。

## 产品目标

让本人和家人在 30 秒内了解本月收支，在两次操作内找到某个分类或日期的原始记录。所有数值来自导入账单；不生成健康评分、不虚构完整月份，不以装饰代替分析。

界面以 Notion 的文档层级、Claude 的暖色阅读体验为参考，形成自己的生活账本视觉。用户已认可 3.0 的配色与布局。3.1 在此基础上增加月份纸卡、滚动阅读层次与微交互，动效与准确标注、可追溯信息共同服务于阅读。

## 已交付迭代：3.1 动态阅读体验

已按 [动效与月度手记规划](动效与月度手记规划.md) 实现首屏、滚动与微交互，保留现有四页结构。同步交付共享月度手记、参与统计的显式月结状态、导入前后差异预览。默认动效与系统 / 手动减少动态效果均经过 Chrome 实测，具体证据见 [3.1 验收记录](验收记录-3.1.md)。

## 已交付迭代：3.2 持续交互与滚动编排

按 [交互动效规划](交互动效规划-3.2.md) 重写纸卡交互，将入场、滚动和指针形变分层；使用真正的滚动时间轴，支持停留与倒放。加入磁吸手记入口、弹簧回位、局部暖光、边线反馈、账单行轻抬、链接下划线、列表错峰与加载扫光。删除装饰性标语，保留统计和操作说明。后续新增动效须验证重复交互、路由往返、键盘焦点及减少动态效果；不能仅凭入场截图验收。

本轮 63 项浏览器检查和 20 项后端回归通过，详见 [3.2 验收记录](验收记录-3.2.md)。家庭远程访问仍是下一阶段主线。

## 第一阶段：本地可用工作台（已实现）

1. **工程**：React / TypeScript / Vite；保留 FastAPI 数据层；实际 shadcn/ui 组件、TanStack Query 请求缓存与取消、页面按需加载。
2. **视觉**：暖纸色、陶土主色、细边线、统一间距；中文标题正常宋体、金额本地 DM Sans；桌面与手机分别组织导航和表格。
3. **数据**：ID 保持字符串；重复导入幂等；最新来源可更正较早日期；预算服务端原子保存；导入错误不进入来源目录。
4. **统计**：最新月按最后记账日标记部分月份，环比使用上一自然月同日区间；不存在可比数据时不给百分比。
5. **完整交互**：真实查询、排序、分页、详情、下钻、导出、预算、预览、确认导入、加载 / 空状态 / 错误重试。
6. **质量闭环**：Chrome DevTools MCP 实页截图和操作；axe-core 辅助扫描；Web Interface Guidelines 人工复核；后端隔离测试和数据校验。

证据以 [验收记录](验收记录.md) 为准。自动检查通过表示所列场景通过，不代表用户审美确认或公网运行验收。

## 第二阶段：家庭远程访问（下一优先级）

目标：家长获得稳定的私人访问地址，刷新即可看见最新数据。

- 选择 NAS / 小型持久服务器；使用单容器、单进程、同源页面与 API。
- 配置域名 / HTTPS / 反向代理访问认证；本人拥有写入令牌，家人只读。
- 对 `data/` 做自动备份并验证恢复；预算、月度手记 / 状态和上传文件一并纳入。
- 为服务加健康检查、容量与失败日志；记录部署和回滚步骤。
- 验收：跨设备访问、拒绝未授权读取 / 写入、重启保留数据、备份实际恢复成功。

仓库已提供 Dockerfile 和 CI 配置；尚未构建验证容器、运行远程 CI 或发布公网服务。GitHub Pages 不作为完整应用后端。

## 第三阶段：账本编辑与数据可靠性

- 分类管理：允许维护分类映射，预览映射结果后应用；保留原始分类与操作记录。
- 更正流程：3.1 已交付同 ID 字段前后差异、变更数量及最多 20 条明细。下一步是全量变更导出、批次历史与撤销；撤销必须与版本事务一起设计。
- 导入事务：暂存整个新版本，再原子切换主数据和清单；对进程中断、磁盘满、并发请求做故障注入。
- 金额模型：从浮点展示迁移到整数分存储和计算，补充边界舍入与退款规则。
- 汇总口径：3.1 已交付显式月结完成 / 仍在记录；后续加入明确覆盖截止日（包括截止日没有消费的情况）、跨年年度切换、退款与多币种规则。当前转账拒绝导入，不计入生活费。
- 验收：原始账单不丢失、变更可追踪和回滚、断电重启不出现混合版本、分类映射无静默损失。

## 第四阶段：分析与阅读体验

- 增加年度对照、预算历史与固定支出识别；先明确统计定义再做图表。
- 由实际家长使用反馈调整字体、留白、信息优先级；不添加没有任务依据的图表。
- 验证真实 Android / iOS Safari、浏览器缩放、屏幕阅读器；扩大长备注和数万条数据的性能测试。
- 月报的可编辑说明及打印手记已在 3.1 实现。后续增加分页稳定的固定版式 PDF；经过人工确认后再加入主动通知。

## 维护约定

每次变更同时更新相关架构与验收记录。新增主流程必须包含成功、加载、空、失败状态。涉及账单统计的改动要有具体样例和后端回归；视觉改动必须查看桌面与手机截图。保留源码、锁文件、可重复运行的验证脚本；依赖、构建产物、个人预算和截图留在本地。旧实现追溯 Git，不再恢复废弃目录。
