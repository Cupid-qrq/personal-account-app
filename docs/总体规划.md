# Ledger Atlas 全面重构总体规划

## 产品定位

Ledger Atlas 面向本人和家长两个读者：本人需要导入、核对和分析，家长需要快速看懂月度收入、支出、结余和变化原因。产品的核心单位是“一个月的生活”，页面需要同时支持快速浏览和追溯原始明细。

视觉方向采用克制的 Notion / Claude 式信息层级：暖白纸面、石墨导航、细线分隔、少量青绿色和琥珀色信号；用 SVG、CSS 图形和明确的数字层级承载科技感，不依赖装饰性渐变或默认图表皮肤。

## 目标架构

### 数据层

- CSV/XLSX/XLS 进入同一个导入器。
- `ID` 是幂等主键，重复导入只覆盖同一条记录，不制造重复账目。
- 标准化、分类别名、缺失字段、金额和时间规则集中在一个数据契约中。
- SQLite 是本地查询存储，CSV 是可读快照，月度 CSV 是家庭备份，manifest 是来源与哈希证据。
- 每次重建都可以从 `data/origin/` 独立复现，不依赖上一次运行状态。

### 后端

- FastAPI 提供健康检查、摘要、模式、明细、数据室和导入接口。
- 分析层只返回 JSON，不负责 HTML 或页面布局。
- 导入接口可用 `LEDGER_ADMIN_TOKEN` 保护；只读 GET 不需要登录，适合家长查看。
- 后续如果出现多人并发或远程长期运行，再将 SQLite 换成 PostgreSQL，API 契约不变。

### 前端

- 静态 HTML/CSS/JS，页面和数据接口分离。
- 四个工作区：总览、消费模式、账单明细、数据室。
- 月份选择是全局状态；图表和表格由同一份 JSON 数据驱动。
- 移动端压缩成单列，明细表允许横向滚动，保证家长在手机上也能读懂。

## 开发阶段

1. **基线迁移**：完成 Excel 兼容、统一契约、全量重建、manifest 和独立 SQLite。当前已完成。
2. **可用产品**：完成 FastAPI、总览、模式、明细、数据室和导入接口。当前已完成首个 alpha。
3. **数据治理**：补充导入预览、错误行报告、分类映射配置、审计日志和备份恢复按钮。
4. **分析增强**：增加预算目标、季度/年度视图、同比、固定支出识别、可解释异常和可下载月报。
5. **生产部署**：同源 API 部署、HTTPS、令牌轮换、定时备份、GitHub Actions 验证和监控。

## 验收标准

- 源目录中的 CSV/XLSX/XLS 可重复重建，记录数、月份和类型分布可由 manifest 复核。
- 同一文件重复导入不改变唯一 ID 总数。
- API 在没有 Streamlit 的情况下返回完整月度摘要和明细。
- 家长只读访问不需要编辑权限；上传接口在配置令牌时拒绝未授权请求。
- 桌面和手机宽度下，首页 KPI、现金流、分类结构和最近记录均可读。
- 每次发布都通过语法、重建、数据质量和 HTTP smoke test，并在迭代日志中记录结果。

## 暂不做的事情

当前不接入外部 LLM，不把规则洞察包装成预测；不在 GitHub Pages 上直接写入隐私账单；不在没有更多月份证据时引入复杂预算模型或投资类指标。
