# 旧项目全面审计记录

审计基线：2026-10-11 工作区现状、Git 历史和 `data/origin/2026-10-11_100114.xlsx`。

## 旧系统做了什么

旧项目以 `app.py` 导入 `src/ui_app.py` 作为 Streamlit 单进程入口。页面层依赖 Streamlit session、tabs、cache 和 Plotly；服务门面在 `src/data_service.py`；`src/data_pipeline.py` 负责 CSV 读取、清洗、按 ID 合并、SQLite 写入、CSV 快照和月度归档；`src/analytics.py` 聚合现金流、分类动量、TopK、Pareto、预算、异常、星期画像和自动摘要；`src/auth.py` 处理应用内置角色登录。

## 旧数据流与证据

1. 原始 CSV 放在 `data/origin/`。
2. `normalize_records()` 补齐 18 个原始字段和三个派生字段。
3. 日常导入把数据合并进 `data/processed/ledger_master.sqlite3`，再导出 `ledger_master.csv`。
4. 全量重建只扫描 CSV，不扫描 XLSX/XLS。
5. `data/archive/` 保存每月 CSV 镜像。

旧主表在审计时为 184 条，覆盖 2026-01 至 2026-05。现有 `2026-10-11_100114.xlsx` 为 387 条累计记录，覆盖 2026-01 至 2026-10；其中 184 条与旧主表按 `ID` 全部重合，新增 203 条，旧主表没有独有记录。新文件有一个额外的 `账本` 字段，收入 25 条、支出 362 条，所有 ID 唯一。

## 已确认的旧系统问题

- **输入范围缺口**：重建路径只扫描 CSV，最新 Excel 不能自动进入数据资产。
- **契约缺口**：`账本` 字段在源数据出现，但旧 `REQUIRED_COLUMNS` 没有定义，重建时会被丢弃。
- **运行时耦合**：页面状态、缓存、导入操作和分析展示都绑定 Streamlit；难以拆成 API、静态前端或移动端。
- **部署语义混乱**：文档同时描述 Streamlit Cloud、Docker、NAS、Heroku，实际入口和数据持久化边界不统一。
- **认证边界弱**：历史版本在默认账号、公开只读和环境变量登录之间多次切换；SQLite 写入没有服务端事务队列或并发锁。
- **验证不完整**：旧验证脚本重点检查 CSV/SQLite 行数和分析冒烟，没有记录源文件哈希、全量输入清单、Excel 解析或 API 合约。
- **可视化依赖重**：Plotly 图表和 Streamlit 组件把交互状态封装在 Python 页面，前端视觉和可访问性难以独立迭代。

## 保留与废弃决策

保留旧 `src/`、历史 CSV 和 Git 历史作为迁移证据；新系统不再把它们作为运行时依赖。新系统建立 `backend/`、`frontend/`、`processed_atlas/` 和 `archive_atlas/` 独立目录，保证新旧版本可以对照回滚。
